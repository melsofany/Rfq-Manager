# نظام الحسابات — الدراسة المحاسبية وطريقة عمل الشركة

> مرجع محاسبي ومحاسبي-تشغيلي لنشاط **كورتوبا للتوريدات (Cortoba Supplies)** — شركة
> **تجارية** (توريدات/توريد وتركيب) تعمل في السوق المصري: تشتري بنودًا من موردين
> وتبيعها لعملائها بضريبة القيمة المضافة. يشرح هذا المستند كيف يجب أن تتكيّف وحدة
> الحسابات في النظام مع طريقة عمل الشركة: القيود، دليل الحسابات، ميزان المراجعة،
> الإقفال الشهري، وعجز ض.ق.م الناتج عن الشراء من موردين غير مسجلين.

---

## 1) نموذج العمل كما يظهر في دورة المستندات

```
طلب تسعير عميل (customer RFQ)
        ↓
طلب عروض من موردين (supplier RFQ) → عروض الأسعار (offers) → اعتماد عرض المورد
        ↓
تسعير العميل (تحقق هامش ≥ 1.06 × تكلفة المورد المعتمدة) → تثبيت الطلب
        ↓
أمر شراء العميل (customer PO)  ──┬──→  أوامر شراء الموردين (supplier PO) → إرسال للمندوب
                                  │
                                  ↓                                     ↓
                          تسليم العميل (delivery)        استلام التوريدات (receipts) + التكاليف
                                  ↓                                     ↓
                          فاتورة بيع (ض.ق.م. 14%)        فاتورة مورد (ض.ق.م. 14% / بدون)
                                  ↓                                     ↓
                          تحصيل من العميل (collections)   دفع للموردين (supplier payments)
                                  ↓                                     ↓
                          ───────────  قيود اليومية  ───────────  ميزان المراجعة  ───  إقفال شهري
```

**الخلاصة المحاسبية:** الشركة دورة توريد كاملة (مخزون عابر أكثر منه مخزونًا دائمًا)،
والوحدة المحاسبية يجب أن تربط **كل أمر شراء عميل** بـ **تكلفته الفعلية** (استلام الموردين

- تكاليف النقل/الشحن/الجمارك المرتبطة ببنود أمر الشراء) لإظهار **الهامش المحقق**
  الحقيقي، لا هامش تقديري.

## 2) الهيكل المحاسبي (دليل الحسابات المعتمد في النظام)

المبنى على العُرف المصري (المنظمات المالية المصرية + متطلبات إقرار ض.ق.م. الشهري):

| النوع      | المدى | أمثلة من النظام                                                                                                                                                                                                                                      |
| ---------- | ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| أصول       | 1xxx  | `1001` النقدية · `1010` البنوك · `1200` العملاء (ذمم) · `1300` المخزون · `1401` ض.ق.م. مدخلات · `1500` دفعات مقدمة للموردين                                                                                                                          |
| خصوم       | 2xxx  | `2100` الموردون (ذمم) · `2401` ض.ق.م. مخرجات · `2402` الخصم تحت حساب مستحق للممول · `2500` مصروفات مستحقة                                                                                                                                            |
| حقوق ملكية | 3xxx  | `3100` رأس المال · `3200` أرباح مرحّلة                                                                                                                                                                                                               |
| إيرادات    | 4xxx  | `4100` المبيعات · `4101` مردود المبيعات · `4900` إيرادات أخرى                                                                                                                                                                                        |
| مصروفات    | 5xxx  | `5100` تكلفة البضاعة المباعة · `5200` رواتب · `5300` إيجارات · `5400/5401/5402` كهرباء ومياه · `5410` اتصالات · `5412` إنترنت · `5700` خدمات تقنية واستضافة · `5750` اشتراكات · `5800` نقل وشحن · `5810` جمارك · `5900` عمولات بنكية · `5990` نثريات |

**الحسابات الرقابية (Control):** العملاء، الموردون، ض.ق.م. مخرجات/مدخلات، المخزون —
تُرحَّل عبر دفتر مساعد (فاتورة/دفعة) لا بقيود مباشرة، لتبقى قابلة للتسوية مع دفاتر
المساعدين. النظام يمنع القيود المباشرة على الحسابات المُعلَّمة `isControl`.

## 3) نموذج الترحيل (Double-Entry) لكل حدث

### 3.1 فاتورة البيع (كل فواتير العملاء بض.ق.م. 14%)

فاتورة بيع بقيمة صافية 10,000 ج.م:

| الحساب               | مدين   | دائن   |
| -------------------- | ------ | ------ |
| العملاء (1200)       | 11,400 |        |
| المبيعات (4100)      |        | 10,000 |
| ض.ق.م. مخرجات (2401) |        | 1,400  |

ويُعترف بتكلفة البضاعة المباعة من واقع الاستلام الفعلي من المورد:

| الحساب                       | مدين  | دائن  |
| ---------------------------- | ----- | ----- |
| تكلفة البضاعة المباعة (5100) | 6,000 |       |
| المخزون (1300)               |       | 6,000 |

> **ملاحظة تطبيقية:** النظام يعتمد الجرد المستمر المبسّط — التكلفة تُعترف عند الترحيل
> من `acceptedQty × finalActualCost` لبند أمر شراء المورد المرتبط + تكاليف البند، لأن
> الشركة تورّد حسب الطلب غالبًا (مخزون عابر).

### 3.2 فاتورة المورد **المسجَّل** (بض.ق.م. 14%)

صافي 4,000 ج.م، خصم تحت حساب المورد 1% (توريدات سلعية):

| الحساب                              | مدين  | دائن  |
| ----------------------------------- | ----- | ----- |
| المخزون / تكلفة البضاعة (1300/5100) | 4,000 |       |
| ض.ق.م. مدخلات (1401)                | 560   |       |
| الموردون (2100)                     |       | 4,520 |
| الخصم تحت حساب مستحق للممول (2402)  |       | 40    |

> الخصم 1% على **صافي الفاتورة قبل ض.ق.م.** (قاعدة الخصم تحت حساب الضريبة).

### 3.3 فاتورة المورد **غير المسجَّل** (بدون ض.ق.م.) — مصدر عجز ض.ق.م

صافي 2,000 ج.م بدون فاتورة ضريبية:

| الحساب                        | مدين  | دائن  |
| ----------------------------- | ----- | ----- |
| المخزون / التكلفة (1300/5100) | 2,000 |       |
| الموردون (2100)               |       | 2,000 |

**الأثر الضريبي = عجز ض.ق.م (VAT deficit).** عند بيع هذه السلعة يُحتسب ض.ق.م. مخرجات
14% على كامل سعر البيع، بينما لا يوجد رصيد مدخلات قابل للخصم يقابلها. الفرق هو **عجز**
تتحمله الشركة ولا يمكن خصمه (لأن الشرط القانوني لخصم ضريبة المدخلات هو وجود
**فاتورة ضريبية** صحيحة تتضمن الرقم الضريبي وقيمة الضريبة). النظام يحسب العجز =
`Σ 14% × صافي المشتريات من موردين غير مسجلين` ويُظهره منفصلًا في تبويب الضرائب
(`vatEvidence.unevidencedInputVat`) حتى يعرفه المحاسب قبل تقديم الإقرار الشهري.

### 3.4 دفعة لمورد

| الحساب                            | مدين  | دائن  |
| --------------------------------- | ----- | ----- |
| الموردون (2100)                   | 4,520 |       |
| الخصم تحت حساب المورد (1410/2402) | 40    |       |
| النقدية/البنك (1001/1010)         |       | 4,560 |

### 3.5 تحصيل من عميل

| الحساب         | مدين   | دائن   |
| -------------- | ------ | ------ |
| النقدية/البنك  | 11,400 |        |
| العملاء (1200) |        | 11,400 |

مع تطبيق الدفعة على أقدم فاتورة بيع غير مسددة أولًا (FIFO) وتحديث رصيدها.

### 3.6 مصروف تشغيلي (كهرباء، إنترنت، مياه، دومين، اشتراكات، نقل، نثريات)

مثال: كهرباء 1,500 ج.م مدفوعة نقدًا:

| الحساب         | مدين  | دائن  |
| -------------- | ----- | ----- |
| كهرباء (5401)  | 1,500 |       |
| النقدية (1001) |       | 1,500 |

النظام يربط فئة المصروف بحسابه تلقائيًا (`EXPENSE_CATEGORY_ACCOUNT`) ويُولّد القيد عند
تسجيل المصروف، فلا يبقى المصروف خارج الدفاتر.

### 3.7 تكاليف بنود أمر الشراء (Trucks/نقل/شحن/جمارك)

تُضاف إلى تكلفة البند (`acceptedQty × finalActualCost + Σ charges`) عند حساب الهامش،
وتُظهر في صفحة الحسابات تحت «المصاريف والتكاليف → تكاليف أوامر الشراء».

## 4) الضرائب المصرية المعتمدة

| الضريبة                       | النسبة الافتراضية | الأساس                   | المرجع                                        |
| ----------------------------- | ----------------- | ------------------------ | --------------------------------------------- |
| ض.ق.م. (VAT)                  | **14%**           | صافي التوريد             | قانون ض.ق.م. 67 لسنة 2016 (وتعديلاته)         |
| خصم تحت حساب المورد — توريدات | **1%**            | صافي الفاتورة قبل ض.ق.م. | قانون الإجراءات الضريبية الموحد 206 لسنة 2020 |
| خصم تحت حساب المورد — خدمات   | **3%**            | صافي الفاتورة قبل ض.ق.م. | نفس المرجع                                    |
| خصم تحت حساب المورد — مهن حرة | **5%**            | صافي الفاتورة قبل ض.ق.م. | نفس المرجع                                    |

- **حد التسجيل في ض.ق.م.:** 500,000 ج.م سنويًا — من لم يبلغه لا يُحصّل ضريبة (ولا يُلزم
  بإقرار)، ما يفسّر وجود موردين صغار غير مسجلين لا يصدرون فواتير ضريبية.
- **الفاتورة الإلكترونية** إلزامية لفئات محددة؛ نظامنا يحتفظ برقم فاتورة المورد
  (`supplierInvoiceNo`) بجانب رقمنا الداخلي للتسوية.
- **قاعدة الخصم:** تُحسب نسب الخصم على صافي الفاتورة (قبل ض.ق.م.)، والنظام يطبّق ذلك في
  `computeInvoice`.
- **الاسترداد:** إذا زادت ضريبة المدخلات عن المخرجات، يُرحَّل الرصيد أو يُطلب استرداده؛
  النظام يعرض `credit` (رصيد دائن مُرحَّل) في تبويب ض.ق.م.

## 5) ميزان المراجعة والقوائم المالية

- **ميزان المراجعة:** يُبنى من أرصدة دليل الحسابات المرحّلة (`accountBalance` لكل حساب)
  ويجب أن يتحقق فيه `Σ مدين = Σ دائن` — النظام يرجّع `balanced` صريحًا.
- **قائمة الدخل:** الإيرادات (4xxx) − المصروفات (5xxx، ومنها تكلفة البضاعة المباعة) =
  صافي الربح، خلال فترة.
- **الميزانية العمومية:** الأصول (1xxx) = الخصوم (2xxx) + حقوق الملكية (3xxx) حتى تاريخ.
  **تنبيه محاسبي:** لتحقيق توازن حقيقي في الميزانية يجب ترحيل **قيد إقفال** شهري/سنوي
  يغلق الإيرادات والمصروفات في الأرباح المرحّلة (`3200`). النظام الحالي يعرض القوائم من
  أرصدة الحسابات مباشرة، ويُستحسن قيد إقفال قبل إصدار الميزانية السنوية.
- **المخزون:** عند إقفال السنة، تُجرى تسوية جردية (زيادة/نقص المخزون) إن وُجد مخزون فعلي.

## 6) الإقفال الشهري (Monthly Closing)

قائمة تحقق قبل الإقفال (مطابقة للممارسة المحاسبية):

1. تحليل كل مستندات الشهر (فواتير بيع/شراء، إيصالات، مصروفات).
2. تسجيل كل القيود بمبدأ القيد المزدوج (مدين = دائن) وترحيلها.
3. **لا قيود مسودة (draft) غير مُرحَّلة** في الشهر — النظام يرفض الإقفال إن وُجدت.
4. مطابقة ض.ق.م. (مخرجات/مدخلات) وحساب **عجز الضريبة** من المشتريات غير المُثبتة.
5. تسجيل التسويات الجردية (مستحقات، مقدمات، إهلاك إن وُجد).
6. توزيع تكاليف أوامر الشراء على البنود قبل حساب الهامش النهائي.
7. مراجعة ميزان المراجعة بعد التسويات ⇒ ثم **قفل الشهر**.

**سلوك النظام:** بعد قفل الشهر (جدول `accounting_closings`) يُمنع إنشاء/ترحيل/إلغاء أي
قيد بتاريخ داخل ذلك الشهر (`assertMonthOpen`). إلغاء القفل متاح للمسؤول فقط ومسجّل في
سجل التدقيق.

## 7) القواعد المحاسبية المدمجة في النظام

| القاعدة                                    | التطبيق                                                                      |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| كل فاتورة عميل بض.ق.م. 14%                 | `sales-invoices.ts` يحسب `net` ثم `vat = net × 14%` ثم `gross`.              |
| المورد غير المسجل ⇒ لا ض.ق.م. مدخلات       | `computeInvoice(..., hasVat=false)` يجعل `vat=0` والقيمة كلها تكلفة → عجز.   |
| خصم تحت حساب المورد على الصافي قبل الضريبة | `withholding = net × rate%`.                                                 |
| توريد بض.ق.م. من العميل + مخزون بالتكلفة   | من واقع الاستلام الفعلي `acceptedQty × finalActualCost`، لا الكمية المطلوبة. |
| الهامش المحقق = البيع − التكلفة الفعلية    | `/accounts/margins` يجمع الاستلام + تكاليف البنود في التكلفة.                |
| الحسابات الرقابية لا تستقبل قيودًا مباشرة  | `isControl` + دفتر مساعد (فواتير/دفعات).                                     |
| أقفال الشهور                               | `assertMonthOpen` في مسار الترحيل.                                           |
| الفرز الزمني للتحصيل                       | تطبيق الدفعة على أقدم فاتورة غير مسددة أولًا.                                |

## 8) خريطة الشاشات الجديدة في `/accounts`

1. **سجل الحركات** — أوامر شراء العملاء (+ أمر شراء الموردين) التي **تم تسليمها/استلامها
   فقط**، بقيمها المحاسبية النهائية والهامش المحقق. الأمر الجاري لا يظهر هنا.
2. **المصاريف والتكاليف** — المصاريف التشغيلية (كهرباء/إنترنت/مياه/دومين/اشتراكات/نقل/
   نثريات…) + تكاليف بنود أوامر الشراء.
3. **الترحيل المحاسبي** — قيود اليومية، فواتير البيع والتحصيل، فواتير الموردين والخصم،
   دليل الحسابات، القوائم المالية، الضرائب، والإقفال الشهري.

## 9) المراجع

- قانون ضريبة القيمة المضافة رقم 67 لسنة 2016 (مصر) وتعديلاته — 14%، الفاتورة الضريبية
  شرط لخصم المدخلات، عدم قابلية خصم ضريبة المدخلات على المعفى.
- قانون الإجراءات الضريبية الموحد رقم 206 لسنة 2020 — الخصم تحت حساب الضريبة (1% / 3% / 5%).
- مصلحة الضرائب المصرية (ETA) — حد التسجيل 500 ألف جنيه، الفاتورة الإلكترونية.
- الممارسة المحاسبية للدفاتر: الدورة المحاسبية، دفتر اليومية → الأستاذ → ميزان المراجعة →
  القوائم المالية → الإقفال.

> هذا المستند مرجع تشغيلي داخلي؛ قبل الاعتماد الضريبي النهائي تُراجع النسب والتعديلات
> السارية مع مصلحة الضرائب أو مستشار ضريبي معتمد.
