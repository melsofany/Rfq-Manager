# ربط جهاز البصمة ZKTeco K14 Pro بنظام RFQ Manager

دليل تشغيل. الجهاز يبعت البصمات للسيرفر بنفسه (ADMS Push) — مفيش جسر ومفيش فتح بورتات في المقر.

---

## 1. إزاي النظام بيستقبل البصمة

```
[K14 Pro]  --(HTTPS 443)-->  [cortoba-rfq.onrender.com]
   في المقر                      /iclock/cdata
```

الجهاز هو اللي يبدأ الاتصال (Outbound)، فمش محتاج IP عام للمقر ولا Port Forwarding.
مسارات البروتوكول المتركّبة على السيرفر:

| Method   | المسار                            | الوظيفة                        |
| -------- | --------------------------------- | ------------------------------ |
| GET      | `/iclock/cdata?SN=…&options=all`  | المصافحة → يرد بإعدادات الجهاز |
| POST     | `/iclock/cdata?SN=…&table=ATTLOG` | بصمات الحضور                   |
| GET      | `/iclock/getrequest?SN=…`         | نبضة القلب                     |
| POST     | `/iclock/devicecmd?SN=…`          | نتائج الأوامر                  |
| GET      | `/iclock/ping?SN=…`               | فحص الاتصال (Firmware حديث)    |
| GET/POST | `/iclock/registry?SN=…`           | تسجيل الجهاز (Push 3.x)        |

> **مهم**: المسار `/iclock` **بدون** `/api`. ده مسار ثابت في فِرمْوِير ZKTeco ومينفعش يتغيّر.

## 2. إعدادات الجهاز نفسه

### 2.1 الشبكة

`Menu` → `Comm.` → `Ethernet`

| الإعداد    | القيمة                                                   |
| ---------- | -------------------------------------------------------- |
| DHCP       | ON (أو IP ثابت خارج نطاق الـDHCP)                        |
| DNS Server | **`8.8.8.8`** ← لو فاضي الجهاز مش هيقدر يحلّ اسم السيرفر |
| Gateway    | IP الراوتر                                               |

### 2.2 خادم السحابة (ADMS)

`Menu` → `Comm.` → `Cloud Server Setting`

| الحقل               | القيمة                                |
| ------------------- | ------------------------------------- |
| Server Mode         | `ADMS`                                |
| Enable Domain Name  | **ON** (لأننا بنستخدم اسم نطاق مش IP) |
| Server Address      | `cortoba-rfq.onrender.com`            |
| Server Port         | `443`                                 |
| Enable Proxy Server | `OFF`                                 |
| HTTPS               | `ON` (لو الخيار موجود)                |

بعد الحفظ: اعمل ريستارت للجهاز، وبعدين من `Cloud Server Setting` دوس **Test** — المفروض يقول نجح.

### 2.3 ساعة الجهاز — ⚠️ الأهم

`Menu` → `System` → `Date Time`

- [ ] الوقت والتاريخ صح (النظام بيخزّن الوقت زي ما الجهاز بعته بالظبط).
- [ ] **Time Zone = GMT+02:00** (مصر). لو غلط، كل بصمة هتتسجّل بفرق ساعتين أو أكتر.
- [ ] NTP Server = `time.google.com` (لو متاح) عشان الساعة متعملش Drift.

> النظام **مش** بيصلّح الوقت. لو ساعة الجهاز غلط، الحضور هيطلع غلط.

### 2.4 الـPIN لكل موظف

`Menu` → `User Mgt.` → اختار/أضف الموظف → `User ID`

اكتب الـ`User ID` ده بعينه في خانة **`biometricPin`** للموظف في صفحة `/hr` → تبويب «الموظفون».
لو الـPIN مش مربوب، البصمة **بتتخزّن** لكن مش بتتربط بموظف، والموظف يظهر «غايب».

## 3. تفعيل الجهاز في النظام

1. بعد أول اتصال ناجح، افتح `/hr` → تبويب **«الأجهزة»**.
2. هتلاقي الجهاز ظاهر بالرقم التسلسلي (SN) وحالته **«قيد الانتظار»**.
3. دوس **«تفعيل»**.
4. (اختياري) سمّي الجهاز ومكانه من `PATCH /api/hr/devices/:sn` (`name` / `location`).

> **قبل التفعيل البصمات بتُرفض.** ده مقصود: أي جهاز مجهول يتصل بالسيرفر مايقدرش يحقن بصمات.
> الرفض بيتم **مع** إرجاع `OK` للجهاز — لو رجّعنا خطأ، الفِرمْوِير هيفضل يعيد نفس الدفعة للأبد.

### الرقم التسلسلي

`Menu` → `System` → `Device Info` → `Serial Number`

## 4. التأكد إن كل حاجة شغالة

### 4.1 فحص سريع من المتصفح

افتح:

```
https://cortoba-rfq.onrender.com/iclock/cdata?SN=<الرقم التسلسلي>&options=all
```

المفروض تشوف نص زي:

```
GET OPTION FROM: <الرقم التسلسلي>
ATTLOGStamp=None
...
ServerVer=3.0.1
PushProtVer=2.4.1
SupportPing=1
```

لو شفت **صفحة HTML** بدل النص ده → الراوتر مش مركّب صح (اتكلم مع المطوّر).

### 4.2 بصمة تجريبية

1. بصّم إصبعك على الجهاز.
2. افتح `/hr` → تبويب **«الأجهزة»** → اتأكد إن «آخر اتصال» اتحدّث.
3. `/hr` → تبويب **«الحضور»** → اختار التاريخ → هتلاقي أول دخول وآخر خروج.

لو البصمة وصلت لكن الموظف «غايب» → الـ`biometricPin` مش مربوب (شوف 2.4).

## 5. متغيرات البيئة (اختياري)

| المتغير           | الافتراضي | الوظيفة                                                                               |
| ----------------- | --------- | ------------------------------------------------------------------------------------- |
| `ADMS_DEVICE_KEY` | (فاضي)    | لو اتحدّد، الجهاز لازم يبعت `?key=<القيمة>`. فاضي = مفتوح (الاعتماد على تفعيل الـSN). |

> **ملاحظة أمنية**: مسارات `/iclock` **بدون مصادقة** (الجهاز مالوش Login).
> الحماية الحالية: الـSN هو المفتاح + الأجهزة المجهولة بصماتها تُرفض لحد التفعيل.
> لو عايز تشفير مشترك، حدّد `ADMS_DEVICE_KEY` وظبّط نفس المفتاح في الجهاز.

## 6. حل المشاكل

| العرض                                | السبب المحتمل                | الحل                                                 |
| ------------------------------------ | ---------------------------- | ---------------------------------------------------- |
| الجهاز مش بيظهر في `/hr` → «الأجهزة» | الجهاز مش واصل للسيرفر       | راجع 2.1 (DNS=`8.8.8.8`) و2.2، ودوس Test             |
| الجهاز بيظهر لكن البصمات مش بتتخزّن  | الجهاز «قيد الانتظار»        | فعّله من تبويب «الأجهزة»                             |
| البصمة بتتخزّن لكن الموظف «غايب»     | `biometricPin` مش مربوب      | اكتب الـ`User ID` في خانة `biometricPin`             |
| الوقت غلط / تأخير مش منطقي           | Time Zone أو ساعة الجهاز غلط | راجع 2.3                                             |
| `Test` بيفشل                         | DNS فاضي أو المنفذ غلط       | DNS=`8.8.8.8`، Port=`443`                            |
| البصمات القديمة مش بتوصل             | الـStamp بيرجّع الفرق بس     | النظام بيطلب `Stamp=None` (كل السجل) — أعد الريستارت |
